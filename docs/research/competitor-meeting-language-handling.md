# How open-source competitors handle a Meeting's language

Researched 2026-10-29. The question: in the source code of open-source meeting transcribers, how is the spoken language chosen? Is it fixed by the person, detected, or both? When does detection run, which model does it, what happens when the language changes mid-meeting, and how is the choice stored? This builds on two earlier notes and does not redo them:

- [language-detection.md](language-detection.md) covers Apple-native options (no public language ID; the private `LanguageDetector`; the confidence race) and what Granola, MacWhisper, Superwhisper and Notion *document*.
- [prior-art-minute-meeting-transcriber.md](prior-art-minute-meeting-transcriber.md) covers Minute and pasrom in general. It notes pasrom's `de` default and its Parakeet language hint. Both repos are re-read here for language handling only.

Method: shallow clones, read but never built or run, plus GitHub issues and PRs. Every claim links to a file and line range at a pinned commit. Anything I concluded myself is marked **(inference)**. Anything I could not settle is marked **unverified**.

## Summary

| Project | Fixed / auto | When detection runs | Detector | Mid-meeting switch | Default | Stored as |
|---|---|---|---|---|---|---|
| **Anarlog** | Both: a **main language + "spoken languages" list** | Local Whisper: every chunk, **only among the listed languages**. Deepgram batch: per file. Apple Speech live: **no detection, first listed language only** | whisper.cpp `lang_detect`; Deepgram `detect_language=<codes>`; Gladia | Deepgram live: `language=multi` (code-switching model). Otherwise no; re-transcribe after | Main language from macOS's first preferred language; extra list empty | Global setting. Summary language chosen afterwards from transcript text |
| **Meetily** | Both: "Auto", "Auto → translate to English", or a fixed language | **Every VAD segment** (a few seconds) | whisper.cpp built-in auto-detect | Happens implicitly, segment by segment. Summary language detected from text and stored per meeting |
| **Screenpipe** | Both: a language list, empty = auto | Batch: every 30 s chunk. Live local: was per 2–6 s chunk until forced (#5650) | whisper.cpp `lang_detect`, restricted to the list; Deepgram `detect_language` | Deepgram live: `language=multi` when no single language | Empty list = auto | Global setting |
| **pasrom** | Both, per engine | WhisperKit: per 30 s window. Parakeet: none (script filter only) | WhisperKit `detectLanguage` | No. Live captions **need a fixed language**; auto falls back to slow re-transcribe | Whisper `de`, Parakeet auto | Global `UserDefaults` |
| **Minute** | Both: `auto` or a fixed language | Once per file (whisper.cpp's first window) | whisper.cpp | No | `auto` | Global `UserDefaults` |
| **Vexa** | Both, per bot | **Every transcription window** (a few seconds of one speaker) | faster-whisper | Yes, implicitly per window, each segment stamped with its language. Windows with language probability < 0.3 are dropped | Auto | Per bot request |
| **Attendee** | Mostly passes through to the provider | Provider-defined; per utterance | Deepgram `multi`, AssemblyAI, Gladia, ElevenLabs, or platform captions | Deepgram `multi` code-switches. Meet/Teams caption language can be changed live via API | Zoom: Deepgram `multi`; Meet/Teams: platform captions | Per bot |
| **noScribe** | Auto, fixed, or "Multilingual" | Auto: once per file, on VAD'd speech. Multilingual: every 30 s segment | faster-whisper | Only in Multilingual mode | `auto` | Remembers the last choice |
| **VoiceInk** (dictation) | Both, per "Mode" | Whisper models only; Apple Speech is fixed | Model-dependent | n/a | `en` | **Per Mode, and Modes switch by front app** |
| **Buzz** (live mic) | Both | Every 5 s live chunk | openai-whisper / faster-whisper | Implicitly, per chunk | Auto | Global |

Patterns, in one line each:

1. **Everyone offers a fixed language. Most offer "auto" too.** None of the meeting apps detects a language with no option to fix it.
2. **"Languages I speak" is a candidate set, not the Meeting's language.** Anarlog learned this the hard way (PR #6328, below). Screenpipe and Anarlog restrict Whisper's detection to the person's list.
3. **Detection on short chunks is the main source of bugs.** Screenpipe, Meetily and Buzz detect per few-second chunk. Screenpipe and Meetily both have issues about wrong-language or wrong-script output that are fixed by forcing a language.
4. **Live engines want one fixed language.** pasrom's live captions, Anarlog's Apple Speech path and Deepgram's streaming API all need it up front. Deepgram's only live alternative is its code-switching `multi` model.
5. **Silent English fallbacks are everywhere**: WhisperKit, Deepgram with no language, Minute's retry, Meetily's `auto-translate`. Each produced real bug reports.
6. **The language is a global setting** almost everywhere. Nobody stores it per calendar event. Two apps (Anarlog, Meetily) detect the *summary* language from transcript text after the fact.

## 1. Anarlog (Hyprnote)

Prefix **A** = `https://github.com/fastrepl/anarlog/blob/a7dadfbb9477177723cab1e140ae06b4e868ecc5/`

### Settings model

- Two global settings: `ai_language` (default `"en"`) and `spoken_languages` (default `"[]"`), both under `language` ([A schema.ts#L274-L283](https://github.com/fastrepl/anarlog/blob/a7dadfbb9477177723cab1e140ae06b4e868ecc5/apps/desktop/src/settings/schema.ts#L274-L283)).
- The transcription candidates are the main language followed by the extra languages, de-duplicated by base code ([A capabilities.ts#L334-L356](https://github.com/fastrepl/anarlog/blob/a7dadfbb9477177723cab1e140ae06b4e868ecc5/apps/desktop/src/stt/capabilities.ts#L334-L356)).
- First run seeds the main language from the OS's preferred languages; extra languages start empty (PR [#6526](https://github.com/fastrepl/anarlog/pull/6526): "Seed only the main language from macOS"). An earlier version copied the whole OS list in, and that was reverted.
- There is no per-session language. Both live start and batch re-transcription read the global settings ([A useStartListening.ts#L147](https://github.com/fastrepl/anarlog/blob/a7dadfbb9477177723cab1e140ae06b4e868ecc5/apps/desktop/src/stt/useStartListening.ts#L147), [A useRunBatch.ts#L340-L342](https://github.com/fastrepl/anarlog/blob/a7dadfbb9477177723cab1e140ae06b4e868ecc5/apps/desktop/src/stt/useRunBatch.ts#L340-L342)). The batch call accepts an `options.languages` override, but I found no caller that passes one **(unverified)**.

### Detection only among the person's languages

- Local Whisper: zero languages → whisper.cpp auto-detect; one → forced; two or more → run `lang_detect` on the chunk and **pick the highest-probability language among the listed ones only** ([A whisper-local/src/model/actual.rs#L227-L262](https://github.com/fastrepl/anarlog/blob/a7dadfbb9477177723cab1e140ae06b4e868ecc5/crates/whisper-local/src/model/actual.rs#L227-L262)). It runs on every `transcribe` call, so on every chunk **(inference)**.
- Argmax / Parakeet: always one language, `detect_language=false` when the person set any. Parakeet v3 takes the first listed language it supports, else English ([A argmax/language.rs#L11-L45](https://github.com/fastrepl/anarlog/blob/a7dadfbb9477177723cab1e140ae06b4e868ecc5/crates/owhisper-client/src/adapter/argmax/language.rs#L11-L45)).
- Deepgram ([A deepgram/language.rs#L45-L73](https://github.com/fastrepl/anarlog/blob/a7dadfbb9477177723cab1e140ae06b4e868ecc5/crates/owhisper-client/src/adapter/deepgram/language.rs#L45-L73)):
  - no language: batch `detect_language=true`, live `language=en`.
  - one language: forced.
  - several: batch `detect_language=<code>&detect_language=<code>` (restricted detection); live `language=multi` if the model supports that pair, else the first language.
  - The code comment states the lesson: "Configured languages are the ones the user speaks, not the ones spoken in any single meeting. Most meetings are monolingual, so prefer detection over code-switching: `multi` decodes the whole file with a code-switching model and loses accuracy against the language-locked one."

### Known pitfall: list length was treated as "code-switching"

- PR [#6328](https://github.com/fastrepl/anarlog/pull/6328) "detect meeting language instead of forcing code-switching": with main = English and German added, German meetings transcribed badly on Deepgram and Gladia. Any two configured languages turned on Gladia's `code_switching` and Deepgram's `multi`. The fix: several candidates now mean *detection*, and code-switching is opt-in. Deepgram **live** stays degraded because its streaming API has no detection: "A live Deepgram meeting is still degraded until re-transcribed."
- PR [#7488](https://github.com/fastrepl/anarlog/pull/7488): mixed-language batch requests could fall back to single-language detection and "return only the dominant language, silently dropping other speech". Now unsupported pairs are refused up front.

### Apple SpeechTranscriber path (the closest analogue to Carbon)

- Live Apple Speech uses **only the first listed language** that Apple supports ([A capabilities.ts#L358-L388](https://github.com/fastrepl/anarlog/blob/a7dadfbb9477177723cab1e140ae06b4e868ecc5/apps/desktop/src/stt/capabilities.ts#L358-L388)). When languages are dropped, a persistent toast says "Live transcription is using {X}… won't include {Y}. Audio is still being saved", with a "Change" button ([A useStartListening.ts#L265-L281](https://github.com/fastrepl/anarlog/blob/a7dadfbb9477177723cab1e140ae06b4e868ecc5/apps/desktop/src/stt/useStartListening.ts#L265-L281)).
- The session locale is the first requested language **that the person has also added in System Settings**. With no request, it is the first System Settings language ([A transcribe-speechanalyzer/src/lib.rs#L320-L337](https://github.com/fastrepl/anarlog/blob/a7dadfbb9477177723cab1e140ae06b4e868ecc5/crates/transcribe-speechanalyzer/src/lib.rs#L320-L337)). Asset installs are refused for other languages: "Apple Speech can only install languages added in System Settings" ([A lib.swift#L206-L214](https://github.com/fastrepl/anarlog/blob/a7dadfbb9477177723cab1e140ae06b4e868ecc5/crates/transcribe-speechanalyzer/swift-lib/src/lib.swift#L206-L214)). Whether that is Apple's rule or Anarlog's own policy is **unverified**; Carbon downloads any supported locale today.
- **Pitfall worth copying:** "`supportedLocale(equivalentTo:)` echoes unknown tags back rather than returning nil (it answers `nb-NO` for Norwegian, which Apple Speech does not transcribe), so its answer is only trusted after checking it against `supportedLocales`" ([A lib.swift#L128-L140](https://github.com/fastrepl/anarlog/blob/a7dadfbb9477177723cab1e140ae06b4e868ecc5/crates/transcribe-speechanalyzer/swift-lib/src/lib.swift#L128-L140)). On macOS 27.0.1 (26A434) it does not reproduce: a probe got `nil` for `nb_NO` and `pl_PL`, and `fr_LU` mapped to `fr-CH`, which is supported. It may still happen on macOS 26, Carbon's deployment target **(unverified)**.
- When `maximumReservedLocales` is reached, it releases some other reserved locale to make room ([A lib.swift#L172-L190](https://github.com/fastrepl/anarlog/blob/a7dadfbb9477177723cab1e140ae06b4e868ecc5/crates/transcribe-speechanalyzer/swift-lib/src/lib.swift#L172-L190)).
- It requests `.transcriptionConfidence` on the transcriber ([A lib.swift#L119-L126](https://github.com/fastrepl/anarlog/blob/a7dadfbb9477177723cab1e140ae06b4e868ecc5/crates/transcribe-speechanalyzer/swift-lib/src/lib.swift#L119-L126)), but I found no code that uses it to pick a language.

### Language detected after the fact, from text

- Summaries are written in "whichever of [the person's] languages dominates the transcript" (PR [#7960](https://github.com/fastrepl/anarlog/pull/7960)). `dominant_language` runs `whatlang` on each segment with an allowlist of the candidates and weights each by its non-whitespace character count. Ties and unsupported candidates fall back to the main language ([A crates/language/src/dominant.rs#L3-L51](https://github.com/fastrepl/anarlog/blob/a7dadfbb9477177723cab1e140ae06b4e868ecc5/crates/language/src/dominant.rs#L3-L51)). PR [#8057](https://github.com/fastrepl/anarlog/pull/8057) then added an opt-out ("Use main language for summaries").

## 2. Meetily

Prefix **MT** = `https://github.com/Zackriya-Solutions/meetily/blob/a2cb62e827da7ef59f65064c97233efb2313878e/`

- **Options:** `auto` ("Auto Detect (Original Language)"), `auto-translate` ("Auto Detect (Translate to English)"), or an ISO code ([MT LanguageSelection.tsx#L12-L15](https://github.com/Zackriya-Solutions/meetily/blob/a2cb62e827da7ef59f65064c97233efb2313878e/frontend/src/components/LanguageSelection.tsx#L12-L15)). The UI warns: "Auto Detect may produce incorrect results. For best accuracy, select your specific language" ([#L213-L218](https://github.com/Zackriya-Solutions/meetily/blob/a2cb62e827da7ef59f65064c97233efb2313878e/frontend/src/components/LanguageSelection.tsx#L213-L218)).
- **Defaults disagree.** The frontend loads `localStorage.primaryLanguage` or `'auto'` ([MT ConfigContext.tsx#L143-L149](https://github.com/Zackriya-Solutions/meetily/blob/a2cb62e827da7ef59f65064c97233efb2313878e/frontend/src/contexts/ConfigContext.tsx#L143-L149)). The Rust global starts at `"auto-translate"` ([MT lib.rs#L124-L126](https://github.com/Zackriya-Solutions/meetily/blob/a2cb62e827da7ef59f65064c97233efb2313878e/frontend/src-tauri/src/lib.rs#L124-L126)) until the frontend syncs it on mount, a fix labelled "fixes startup desync bug" ([MT ConfigContext.tsx#L217-L226](https://github.com/Zackriya-Solutions/meetily/blob/a2cb62e827da7ef59f65064c97233efb2313878e/frontend/src/contexts/ConfigContext.tsx#L217-L226)). Audio transcribed before that sync would be translated to English **(inference)**.
- **When:** the live worker reads the global preference and calls whisper.cpp **once per VAD speech segment** ([MT worker.rs#L439-L444](https://github.com/Zackriya-Solutions/meetily/blob/a2cb62e827da7ef59f65064c97233efb2313878e/frontend/src-tauri/src/audio/transcription/worker.rs#L439-L444)). `auto` passes no language, so whisper.cpp auto-detects on each segment ([MT whisper_engine.rs#L567-L576](https://github.com/Zackriya-Solutions/meetily/blob/a2cb62e827da7ef59f65064c97233efb2313878e/frontend/src-tauri/src/whisper_engine/whisper_engine.rs#L567-L576)). Live segments close after 500 ms of silence. A code comment measured a 26-minute meeting split into 322 segments with a median of 3.5 s, and notes Whisper "zero-pads the window and leans on its language-model prior" on short clips ([MT pipeline.rs#L738-L757](https://github.com/Zackriya-Solutions/meetily/blob/a2cb62e827da7ef59f65064c97233efb2313878e/frontend/src-tauri/src/audio/pipeline.rs#L738-L757)).
- **Parakeet ignores the language.** It logs "Parakeet doesn't support language preference … transcribing in default language" ([MT parakeet_provider.rs#L28-L34](https://github.com/Zackriya-Solutions/meetily/blob/a2cb62e827da7ef59f65064c97233efb2313878e/frontend/src-tauri/src/audio/transcription/parakeet_provider.rs#L28-L34)), and the picker offers only the two auto options for Parakeet ([MT LanguageSelection.tsx#L133-L136](https://github.com/Zackriya-Solutions/meetily/blob/a2cb62e827da7ef59f65064c97233efb2313878e/frontend/src/components/LanguageSelection.tsx#L133-L136)).
- **After the Meeting:** re-transcription takes a language, but only with Whisper ([MT retranscription.rs#L609-L614](https://github.com/Zackriya-Solutions/meetily/blob/a2cb62e827da7ef59f65064c97233efb2313878e/frontend/src-tauri/src/audio/retranscription.rs#L609-L614)). The summary language is detected from transcript text with `whatlang`, weighted, with a confidence floor ([MT summary/language_detection.rs#L27-L60](https://github.com/Zackriya-Solutions/meetily/blob/a2cb62e827da7ef59f65064c97233efb2313878e/frontend/src-tauri/src/summary/language_detection.rs#L27-L60)), and stored per meeting as `detected_summary_language`, cleared on re-transcription ([MT retranscription.rs#L735-L745](https://github.com/Zackriya-Solutions/meetily/blob/a2cb62e827da7ef59f65064c97233efb2313878e/frontend/src-tauri/src/audio/retranscription.rs#L735-L745)).
- **Issues:**
  - [#581](https://github.com/Zackriya-Solutions/meetily/issues/581) (open), "Add option to manually set a fixed transcription language (disable per-segment auto-detection)": an all-Russian meeting gets "random English text … not a translation, just noise. The real speech at that moment is lost." The reporter's engine is not stated, so whether a fixed Whisper language was available to them is **unverified**.
  - [#370](https://github.com/Zackriya-Solutions/meetily/issues/370) (open): side conversations in Italian or Chinese inside an English meeting come out as "gibberish"; asks to detect switches or ignore off-language speech.

## 3. Screenpipe

Prefix **S** = `https://github.com/screenpipe/screenpipe/blob/f835909b9d96bf2d035e95e9dec9dd23355d04f6/`. Source-available, commercial license.

- **Setting:** a language list; empty means auto (default `languages: vec![]`, [S screenpipe-config/src/recording.rs#L1006](https://github.com/screenpipe/screenpipe/blob/f835909b9d96bf2d035e95e9dec9dd23355d04f6/crates/screenpipe-config/src/recording.rs#L1006)). Live meeting notes get a forced language only when exactly one is listed ([S recording_config.rs#L592-L601](https://github.com/screenpipe/screenpipe/blob/f835909b9d96bf2d035e95e9dec9dd23355d04f6/crates/screenpipe-engine/src/recording_config.rs#L592-L601)).
- **Batch (background) path:** audio is cut into 30 s chunks by default ([S recording.rs#L965](https://github.com/screenpipe/screenpipe/blob/f835909b9d96bf2d035e95e9dec9dd23355d04f6/crates/screenpipe-config/src/recording.rs#L965)). Each chunk runs `lang_detect` ([S whisper/batch.rs#L117-L120](https://github.com/screenpipe/screenpipe/blob/f835909b9d96bf2d035e95e9dec9dd23355d04f6/crates/screenpipe-audio/src/transcription/whisper/batch.rs#L117-L120)), then takes the argmax, **restricted to the listed languages**, or forces the one listed language ([S detect_language.rs#L19-L46](https://github.com/screenpipe/screenpipe/blob/f835909b9d96bf2d035e95e9dec9dd23355d04f6/crates/screenpipe-audio/src/transcription/whisper/detect_language.rs#L19-L46)).
- **Bug history, straight from the code comments:**
  - "The previous implementation cast each probability to `i32`, truncating every value in `[0, 1)` to `0` (english). That is why automatic language detection 'only detected english'" ([S detect_language.rs#L16-L18](https://github.com/screenpipe/screenpipe/blob/f835909b9d96bf2d035e95e9dec9dd23355d04f6/crates/screenpipe-audio/src/transcription/whisper/detect_language.rs#L16-L18); issue [#3550](https://github.com/screenpipe/screenpipe/issues/3550)).
  - Deepgram batch: "WITHOUT any language parameter Deepgram defaults to English and silently drops every other language." Now: none → `detect_language=true`, one → `language=<code>`, many → `detect_language=<code>&…` ([S deepgram/batch.rs#L130-L142](https://github.com/screenpipe/screenpipe/blob/f835909b9d96bf2d035e95e9dec9dd23355d04f6/crates/screenpipe-audio/src/transcription/deepgram/batch.rs#L130-L142)).

## What Carbon can take from this (opinion)

Carbon's constraint stays the same: `SpeechTranscriber(locale:)` fixes one locale per transcriber, Apple has no public language ID, and switching means a new module (see [language-detection.md §4](language-detection.md#4-mid-meeting-language-switches)). Carbon already picks a Meeting Language by hand, keeps a list of chosen languages with a default ([AppModel+Languages.swift](../../App/Sources/AppModel+Languages.swift)), and re-transcribes the live Meeting from the start on a switch.

1. **Keep "languages I speak" and "this Meeting's language" apart.** Carbon's `MeetingLanguages.chosen` and `defaultLanguage` already do this. Anarlog shipped the opposite (list length = code-switching) and had to undo it (#6328). Never read two chosen languages as "this Meeting is bilingual".
2. **If Carbon adds detection, detect only among the chosen languages.** Anarlog and Screenpipe restrict Whisper to the person's list; Deepgram takes `detect_language=<codes>`. For Carbon this is the confidence race from [language-detection.md](language-detection.md) option A, run only over `chosen`. That keeps it to two or three transcribers and under `maximumReservedLocales`.
3. **Decide on about 30 s of speech, never on a few seconds.** Every per-short-chunk detector here produced bug reports: Meetily #581, Screenpipe #5650, and Meetily's own comment on 3.5 s segments. The Whisper engines themselves use a 30 s window. This backs the 20–30 s figure in language-detection.md.
4. **On low confidence, keep the default; never fall back to English.** Vexa drops windows below 0.3 and Attendee skips ElevenLabs results below 0.5. faster-whisper uses a 0.5 threshold and then a majority vote. The silent English fallbacks (WhisperKit #339, Deepgram with no language, Minute's retry, Screenpipe #3550) each caused "auto only produces English" reports. Carbon's fallback should be the person's `defaultLanguage`.
5. **A live engine needs one language. Say which one, visibly.** pasrom's live captions refuse to stream on "auto". Anarlog's Apple Speech path takes the first language and shows a persistent toast naming it, with a "Change" button. Carbon's start banner already names the language ([AppModel+Languages.swift](../../App/Sources/AppModel+Languages.swift) `restateStarted`). Keep the switch one click away during the Meeting, as Granola and Attendee do.
6. **Check `supportedLocale(equivalentTo:)` against `supportedLocales`.** Anarlog reports it echoes unsupported tags back (e.g. `nb-NO`). Carbon's first-run default called it on `Locale.current` and trusted the answer ([AppModel+Languages.swift#L15](../../App/Sources/AppModel+Languages.swift#L15)). A Norwegian Mac might get a locale SpeechTranscriber cannot run. Worth a two-line guard. It does not reproduce on macOS 27.0.1 (see the Anarlog section), but Carbon also runs on macOS 26. Carbon now checks the answer against `supportedLocales`.
7. **Decide per stream, not per Meeting.** No app here detects per mic/system track, but Vexa (per speaker window) and Attendee (per utterance) show that language belongs to a stream of one voice. Carbon's "Me" stream is one person and nearly always the default language. If "Them" is in another language, only that stream needs a race or a switch **(inference)**.
8. **Store the language on the Meeting, and remember it.** Everyone here keeps the language as a global setting; noScribe remembers the last choice; VoiceInk ties it to the front app. Nobody keys it to a calendar event or to the participants. That is open ground for Carbon's EventKit data: "this recurring event was French last time" is a cheap prior (option D in language-detection.md). The Meeting's own frontmatter is the natural place to record the language actually used.
9. **Text-based dominant-language checks only work on text from a multilingual engine.** Anarlog and Meetily run `whatlang` on the transcript to choose the summary language. In Carbon the text comes from a single-locale SpeechTranscriber, which hallucinates text in its own language when the locale is wrong (language-detection.md's experiment: `NLLanguageRecognizer` said English 1.00 on French audio). Such a check would confirm the wrong choice. Use per-word confidence instead.
10. **No translate mode.** Meetily's `auto-translate` default and pasrom #256 show Whisper turning foreign speech into English. SpeechTranscriber has no translate task, so Carbon avoids this pitfall by construction **(inference)**.
